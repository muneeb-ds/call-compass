## Codebase Patterns
- Quality checks run from `backend/` (config lives in `backend/pyproject.toml`), venv is at repo root:
  `cd backend && ../.venv/bin/ruff check . && ../.venv/bin/mypy callcompass && ../.venv/bin/pytest`
- mypy is **strict**: annotate every param and return type, including `-> None` on test functions.
- Python 3.11 is the target. System `python3` is 3.10.8 — always use `.venv/bin/python` (uv-created, 3.11.13).
- Untyped third-party imports need an `ignore_missing_imports` override block in `backend/pyproject.toml`.
- Adding a runtime dep: edit `[project].dependencies`, then `cd backend && uv pip install --python ../.venv -e ".[dev]"`.
- Work happens on branch `ralph/callcompass-mvp` (branched from `main`).
- Full PRD detail (schemas, sample tree JSON, event payloads) is in `tasks/prd-callcompass-mvp.md` —
  read the relevant section verbatim rather than inventing shapes.
- Durable module-level knowledge goes in `backend/CLAUDE.md`; story-by-story notes go here.
- Domain errors are typed exceptions with **single-line** messages naming the offending entity
  (see `TreeConfigError`). Don't let `pydantic.ValidationError` escape a module boundary.
- Pydantic models use `extra="forbid"` + discriminated unions on a `type` field.
- Load the tree via `callcompass.tree.load_tree(default_config_path())` — never re-read or
  re-shape `config/tree.json` by hand.
- `config/tree.json` must stay byte-equivalent (as JSON) to the PRD's "Sample Tree Config".
  Verify with a short `json.loads` comparison against the PRD markdown rather than by eye.
- **Build the FastAPI app via `create_app(model_loader=..., tree_path=...)`**, not a module-level
  `app` with hardcoded deps. `app = create_app()` is production; every test passes
  `model_loader=fake_engine` so the suite needs no model and no network.
- Shared test doubles live in `backend/tests/fakes.py` (`FakeModel`, `fake_engine`); `tests/` is a
  package so `from .fakes import ...` works. Extend these rather than adding a new double.
- Before coding against a third-party package, **read its installed source** in
  `.venv/lib/python3.11/site-packages/<pkg>/` and record the confirmed signatures in
  `backend/CLAUDE.md`. Don't infer an API from the PRD's assumptions.
- One external-API assumption per module, isolated: `tree.py` owns the config shape,
  `tools.py` owns the `neudecide` tool schema, `model.py` owns construction/inference.
  Downstream code consumes those, never the raw shapes.
- When a third-party package exposes a helper that *reads* the shape you emit (e.g.
  `neudecide.grammar.tool_parameters`), round-trip through it in a test — it's a real
  guard against an upstream schema change, and needs no model or network.
- Return **copies** of values read off loaded Pydantic models (`list(x.enum)`), so a
  caller mutating a returned dict can't corrupt the process-wide loaded config.
- Traversal/SSE event payloads are **Pydantic models whose field names are the wire format**
  (see `traversal.py`). `event.event` is the SSE event name, `model_dump()` is the data.
  Check the PRD's "API Endpoints" section before renaming any field.
- Generators are the unit of streaming: compute lazily and yield, so the HTTP layer can
  forward each result the moment it exists rather than buffering a whole run.
- Messages that embed a third-party exception must collapse it with `" ".join(str(exc).split())`
  — upstream errors (e.g. HF's `GatedRepoError`) are multi-line and bury the actionable hint.
- A domain error maps to HTTP status in **one** `@app.exception_handler(...)` inside `create_app`,
  never with a try/except in the route (see `AudioError` → `400 {"detail": ...}`). Routes raise.
- Reject bad input, never silently repair it: `audio.py` won't resample or downmix, because a
  quiet fix-up hides the upstream client bug (PRD R-5) instead of surfacing it.
- Test fixtures are **generated, not checked in** (`tests/fakes.py::make_wav()`); keyword args
  build the invalid variants. No binary files in the repo.
- A generator whose consumer must release it deterministically is annotated
  `-> Generator[T, None, None]`, not `-> Iterator[T]` — `Iterator` has no `.close()` under
  mypy strict. Never `yield` inside a `try/finally` that may be unwinding a `GeneratorExit`.
- Blocking CPU work (`generate()`) is pumped through `asyncio.to_thread` one step at a time so
  the event loop stays free. Testable without pytest-asyncio: `asyncio.run()` a drainer and
  assert the loop's `threading.get_ident()` isn't among the idents the fake recorded.
- The model warmup lives in `load_engine()`, not the lifespan handler, so tests injecting a
  `model_loader` see **zero** warmup calls in `FakeModel.calls`.
- A `StaticFiles` mount at `/` (in `create_app`) matches every path and is GET-only: routes
  registered **after** `create_app()` returns are shadowed and answer 405. Re-append the mount
  (`app.router.routes`) if you add one.
- `frontend/` is vanilla ES modules with no bundler, no node_modules, and **no JS typecheck or
  lint**. Checks available: `node --check frontend/*.js`, plus the backend's serving tests.
  See `frontend/CLAUDE.md` for the module layout and conventions.
- **JS logic that must match a backend contract is tested from pytest by running the shipped
  JS under node** (`tests/encode_fixture.mjs` + `tests/test_frontend_audio.py`) and asserting
  against the real Python decoder/endpoint. Reach for this instead of adding a JS test runner.
- Frontend failures are reported **inline in the column they belong to** (`#capture-message`),
  never `alert()` and never a silent catch.
- `frontend/app.js` **exports** its entry points (`checkHealth`, `wireCapture`) and calls them
  at the bottom, so a later story can reuse them rather than re-deriving the wiring.
  `wireCapture()` returns `{ recorder, waveform, timer, toggle, latest }` — drive those from a
  later story instead of re-querying the DOM.
- A frontend constant that mirrors a backend constant is **derived, never retyped**
  (`timer.js`'s `MAX_RECORDING_MS` comes from `wav.js`'s `MAX_SECONDS`), and pinned by a
  node-run pytest. Hand-writing the same limit twice is how a valid recording becomes a 400.
- All browser audio limits live in `wav.js` (`SAMPLE_RATE`, `MAX_SECONDS`, `clampSamples`);
  it is the only frontend module allowed to know the wire format or trim audio.
- A frontend module takes its **DOM elements as constructor arguments** and never calls
  `document.*`; `app.js` owns every lookup. That is what makes the module loadable from
  node with a handful of stub objects, which is this repo's only JS test path.
- A control with no data yet is **`disabled`, never `hidden`** — the Capture column must
  not change shape mid-demo as widgets appear.
- The configured tree is a **DAG**: two options can share a `next`. De-duplicate when
  walking it, and take the **longest** path from the root as a node's depth.
- Visual state is a `data-state` attribute flipped on an existing element, never a
  re-render and never a parallel CSS class (`idle` / visited / warning on `.tree-node`).
- UI geometry is **derived from the data at render time** and asserted by running the
  shipped JS under node against the real config *and a mutated copy of it* — a layout that
  quietly stopped following `config/tree.json` must fail a test, not a demo.
- No browser tool in this environment. For an SVG story, render the shipped layout to a
  standalone `.svg`, rasterize with `qlmanage -t -s 1200 -o /tmp x.svg`, and Read the PNG.
  **The same works for HTML**: write a standalone `.html` with the real `styles.css`
  inlined and markup serialized from the shipped module, then `qlmanage -t` it. That is
  the closest thing to a visual check for a non-SVG UI story.
- A frontend lookup keyed by a backend enum is **pinned to that enum from pytest**
  (`STOP_REASONS` vs `typing.get_args(StopReason)`), and still needs a readable `??`
  fallback so a new code degrades on screen instead of printing `undefined`.
- A UI module that renders a backend payload is wired through a **hook on `Analysis`**
  (`onTerminal` / `onError` / `onReset`), never by re-reading the stream or by `Analysis`
  touching the DOM itself.
- A control's enabled/disabled state lives in the DOM's own `disabled` property, with
  **no second copy** in the module (`ResetControl.armed` is a getter over it).
- Teardown is **owned by the half that owns the state** (`Analysis.reset()`,
  `capture.reset()`); a cross-cutting action composes those in a pure function whose
  order is assertable, rather than re-deriving what to clear.
- A behaviour that is only wrong **as a sequence** (two runs accumulating, a reset that
  un-draws nothing) needs a fixture that performs the sequence. Single-snapshot
  assertions pass on exactly the bug the story exists to prevent.
- **The real model is runnable now.** `HF_TOKEN` is in the gitignored `.env` at the repo
  root, not auto-loaded: `set -a && . ./.env && set +a` first. First load downloads
  ~43 MB (~18 s), later starts ~1.7 s.
- Real end-to-end runs go through `scripts/bench_latency.py` (boots real uvicorn + real
  model, synthesizes audio with macOS `say` + `afconvert` at 16 kHz mono 16-bit, POSTs to
  `/api/analyze`). Extend it rather than writing another one-off probe.
- **TTS audio is valid for timing, invalid for accuracy.** Latency tracks audio length and
  inference count, not speaker; but the same sentence in two `say` voices takes different
  branches. Never sign off a tree/prompt change on synthetic speech alone.
- **A p95 over 20 samples is the second-slowest run.** It moves with one outlier: repeats
  here held median at 241–286 ms while p95 swung 263–477 ms on a laptop with other apps
  running. Repeat the measurement, report the spread, and say what the machine was doing —
  don't quote a single p95 as if it were stable.
- Verify a documented command by actually running it in a **fresh `git clone` to /tmp**
  with a fresh venv. That is the only way "verified from a clean checkout" means anything.
- Stale `uvicorn` processes from earlier iterations linger for hours. `ps -eo pid,etime,pcpu
  | grep uvicorn` before trusting a manual server check or a benchmark.

    unreachable cycle is still an error.

  - **An AudioWorklet module is a classic script, not an ES module** — `addModule()` gives
    it no `import`. Anything it needs must be inlined, which is why the resampler lives in

    of worklet globals is what makes them loadable from node.

  - **Pin a frontend enum to its backend literal type.** `STOP_REASONS`'s keys are
    asserted equal to `typing.get_args(StopReason)`, so adding a fifth stop reason in

    the only kind of check that catches a silently-unexplained new state. Do the same
    for any other closed set the two sides share.
  - A lookup keyed by a backend code needs a `??` fallback that still reads as a
    sentence — `STOP_REASONS[reason] ?? ...` — because the pin above fails in CI, not on
    the projector, and the demo must degrade to "stopped here (new_code)" rather than
    "undefined".
  - Three terminal looks, **one** markup shape: `card()` builds the header + optional
    latency badge and `show(state, card)` flips `data-state`, so each look is a CSS
    block, not a second serializer branch in the test fixture. The fixture's result
    reader became one function covering all three as a direct result.
  - The `error` payload has no `total_latency_ms`, so the badge is conditional on
    `typeof latencyMs === "number"` — not on truthiness, which would drop a genuine 0.
  - `test_frontend_analysis.py` fixtures that POST to `/api/analyze` should be
    `scope="module"` (`happy_body`, `unplaced_body`, and now `error_body`); a per-test
    traversal is pure waste since the body is deterministic.

  the Capture column. One click cancels any in-flight SSE stream, clears the recording,
  the playback control, the waveform, the clock, the inline capture message, every node
  and edge highlight plus the per-node annotations, the Trace column and its total, and
  the result card — all without a page reload, so the tree is never re-fetched.
- Files changed:
  - `frontend/reset.js` (new): pure `resetAll({analysis, capture})` (the teardown, in the
    one safe order — cancel *then* clear) and `ResetControl(button, onReset)` with
    `arm()` / `disarm()` / `armed` / `trigger()`.
  - `frontend/app.js`: `wireCapture()` gained a `reset()` (discards a take still in
    progress so the mic indicator can't be left lit) and exposes it; `wireAnalysis` takes
    an `onFinish` hook fired on a terminal event, an `error` event, or a rejected upload —
    but **not** on an abort; `main()` builds the `ResetControl` and returns it.
  - `frontend/index.html`: `#reset-slot` is a real `<button id="reset-button">`, shipping
    `disabled` in the markup, replacing the US-008 placeholder.
  - `frontend/styles.css`: `.reset-slot` / `.reset` (ghost outline, dim, `:disabled`
    grayed), and `.placeholder.bottom` generalized to `.bottom`.
  - `backend/tests/reset_fixture.mjs` + `backend/tests/test_frontend_reset.py` (new,
    11 tests): node drives the shipped control through **run → reset → run** over a real
    `/api/analyze` body, asserting the enablement sequence per frame, the full teardown,
    non-accumulation across two runs, and the mid-flight cancel.
  - `backend/tests/test_app.py` (`/reset.js` is served), `frontend/CLAUDE.md`,
    `backend/CLAUDE.md`.
- Verified: `ruff check .` clean, `mypy callcompass` clean (8 files), `mypy tests` clean
  (14 files), `pytest` 179 passed (was 168). `node --check` clean on the changed JS.
  Booted a live uvicorn with the fake engine: `/`, `/styles.css`, `/app.js`, `/reset.js`,
  `/api/health` all 200 with the right content types, and the served HTML carries
  `id="reset-button"`.
- **Browser verification: NOT done — still no dev-browser/MCP browser tool here.**
  Instead the Capture column was rendered from the shipped `index.html` markup with the
  real `styles.css` inlined, in both Reset states, and rasterized with `qlmanage -t -s 900`:
  the button sits flush at the foot of the column in both, reads as clearly secondary
  beside the Record circle, and is visibly grayed when disarmed without the column
  changing shape. A human should still click through run → reset → run on the real page.
- **Reading of the two ACs that pull against each other:** "disabled before any run has
  finished" is implemented literally, so during the *first* run the button is disabled —
  which is harmless, because US-013 already disables Record for the whole traversal, so
  there is nothing to interrupt. "Reset cancels any in-flight stream" is therefore
  reachable from run 2 onward: the button stays armed after a run ends and is only
  disarmed by its own press. `test_reset_cancels_an_in_flight_stream` exercises exactly
  that state (`--arm-first`).
- **Learnings for future iterations:**
  - **Order matters in the teardown, and only a sequence test catches it.**
    `analysis.cancel()` must precede `analysis.reset()`; reversed, a chunk already read
    lights a node back up after the tree has been dimmed. That is why the teardown is a
    pure exported function rather than three statements inside a click handler.
  - An abort is **not** a finish: `onRecording`'s `AbortError` branch must return without
    calling `onFinish`, or Reset re-arms itself immediately after clearing and the button
    never returns to its initial state.
  - Non-accumulation was already true before this story (`Analysis.run()` calls
    `reset()` first), but nothing proved it. The new fixture runs the same body twice and
    asserts the second run's cards/total/picks/annotations **equal** the first run's —
    which is a stronger and more readable assertion than counting.
  - A fixture that appends per-frame observations across several runs has to snapshot the
    list between them (`armedPerFrameFirstRun`), or the second run silently doubles it.
    Cost one failing assertion to notice.
  - `qlmanage` can compare two states side by side in one image: duplicate the section
    into a two-column grid with the attribute flipped. Cheaper than two renders, and the
    difference is the thing being judged.
  - `main()` builds `ResetControl` **before** `analysis` and `capture` exist and closes
    over them; the `const` TDZ is fine because the closure only runs on a click. The
    alternative (threading a controller through both wiring functions) would have put
    teardown knowledge in three places.

    model by hand" section with the TTS and benchmarking caveats.

  `mypy --strict scripts/bench_latency.py` clean, `pytest` 179 passed.
  **Install commands verified from an actual clean checkout**: fresh `git clone` to
  `/tmp/cc-clean`, fresh `uv venv` + `uv pip install -e "backend[dev]"`, then all three
  quality checks green there (179 passed).
- **Latency: measured, not estimated.** 4x20 runs against the real model on an Apple M3 Pro
  (q4, CPUExecutionProvider). Headline 20-run figures: total_latency_ms median **242 ms**,
  p95 **263 ms**, min 50 ms. Pooled over all 80 runs: median 245 ms, p95 353 ms. A
  3-inference path is ~276 ms median; the 1-inference short circuit/decline ~67 ms.
  Well inside the PRD's 1 s budget.
- **Demo script is genuinely pre-verified** (PRD R-1): every utterance in the README table
  was confirmed to reach its listed leaf on two different `say` voices, and all 80 benchmark
  runs resolved as intended — only the off-topic utterance came back `unplaced`. This also
  closes the human-verification gap US-015 left open: the `unplaced` path has now been
  exercised against the real model with real (if synthetic) off-topic audio, not a fake.
- **Learnings for future iterations:**
  - **The sample tree asks three questions of one sentence.** An utterance carrying only an
    intent ("what does Pro cost?") legitimately stops at `product_interest` or `signal_check`
    with `empty_response` — the model is declining because the signal genuinely isn't there,
    not malfunctioning. A first draft of the demo script failed this way on 5 of 6 lines;
    the utterances that demo well state intent **and** team size **and** objection. Any
    future demo content or tree edit has to respect that or it looks broken on stage.
  - **TTS is fine for timing, misleading for accuracy.** `say -v Samantha` and `say -v Daniel`
    on the identical sentence took different branches and disagreed on outcome in ~a third of
    the probes. Latency depends on audio length and inference count, so the benchmark is
    sound; branch accuracy on synthetic speech is not evidence about a human voice. The
    README says so explicitly rather than letting the reader over-read the numbers.
  - **p95 over 20 samples is just the second-slowest run.** Four repeats held the median at
    241–286 ms but moved p95 across 263–477 ms, tracking background load (Steam was holding
    a core; load average ~4–6). Reporting one p95 as a fact would have been false precision —
    the README gives the quietest run, the pooled 80-run figure, the observed range, and what
    the machine was doing.
  - The out-of-enum argument values predicted back in US-003/US-004 are **real and observable**
    on the live model: `pricing_focus='sales'`, `growth_signal='dashboards'`,
    `decline_tone='thanks'`. The advisory-enum decision in `traversal.py` (log, pass through,
    branch on tool name) is right, and the README documents the behaviour so an operator
    seeing a stray value in the trace doesn't read it as a bug.
  - Verify documented install commands in a **fresh clone to /tmp**, not in the working tree —
    the working tree has a built venv and an editable install already, so it cannot fail.
  - `qlmanage`-style visual checking wasn't needed here (no UI change), but note no browser
    tool is available in this environment; the browser-verification gaps flagged in US-008
    through US-016 remain open for a human.
