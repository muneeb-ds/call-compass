## Codebase Patterns
- Quality checks run from `backend/` (config lives in `backend/pyproject.toml`), venv is at repo root:
  `cd backend && ../.venv/bin/ruff check . && ../.venv/bin/mypy callcompass && ../.venv/bin/pytest`
- mypy is **strict**: annotate every param and return type, including `-> None` on test functions.
- Python 3.11 is the target. System `python3` is 3.10.8 — always use `.venv/bin/python` (uv-created, 3.11.13).
- Untyped third-party imports need an `ignore_missing_imports` override block in `backend/pyproject.toml`.
- Adding a runtime dep: edit `[project].dependencies`, then `cd backend && uv pip install --python ../.venv -e ".[dev]"`.
- Work happens on branch `ralph/callcompass-mvp` (branched from `main`).
- Full PRD detail (schemas, sample tree JSON, event payloads) is in `tasks/prd-callcompass-mvp.md` —
  read the relevant section verbatim rather than inventing shapes.
- Durable module-level knowledge goes in `backend/CLAUDE.md`; story-by-story notes go here.
- Domain errors are typed exceptions with **single-line** messages naming the offending entity
  (see `TreeConfigError`). Don't let `pydantic.ValidationError` escape a module boundary.
- Pydantic models use `extra="forbid"` + discriminated unions on a `type` field.
- Load the tree via `callcompass.tree.load_tree(default_config_path())` — never re-read or
  re-shape `config/tree.json` by hand.
- `config/tree.json` must stay byte-equivalent (as JSON) to the PRD's "Sample Tree Config".
  Verify with a short `json.loads` comparison against the PRD markdown rather than by eye.
- **Build the FastAPI app via `create_app(model_loader=..., tree_path=...)`**, not a module-level
  `app` with hardcoded deps. `app = create_app()` is production; every test passes
  `model_loader=fake_engine` so the suite needs no model and no network.
- Shared test doubles live in `backend/tests/fakes.py` (`FakeModel`, `fake_engine`); `tests/` is a
  package so `from .fakes import ...` works. Extend these rather than adding a new double.
- Before coding against a third-party package, **read its installed source** in
  `.venv/lib/python3.11/site-packages/<pkg>/` and record the confirmed signatures in
  `backend/CLAUDE.md`. Don't infer an API from the PRD's assumptions.
- Messages that embed a third-party exception must collapse it with `" ".join(str(exc).split())`
  — upstream errors (e.g. HF's `GatedRepoError`) are multi-line and bury the actionable hint.

- Verified: `ruff check .` clean, `mypy callcompass` clean (3 files), `pytest` 20 passed.
- **Learnings for future iterations:**
  - Pydantic v2 catches `ValueError`/`AssertionError` in validators and wraps them in a
    `ValidationError`, but lets **other** exception types propagate untouched. That's how
    `TreeConfigError` escapes nested validators with a clean single-line message. Validators
    that know the node id raise `TreeConfigError`; the ones that don't (e.g. `Option`) raise
    `ValueError` so Pydantic's `loc` can supply the id in `_single_line`.
  - A duplicate node id in JSON is invisible after `json.loads` (dicts dedupe). Needed an
    `object_pairs_hook` to catch it. Any future config file needs the same treatment.
  - `Field(min_length=1)` on a `list[str]` is how "enum must be non-empty" is enforced
    structurally — no custom validator needed. Same trick for `options` and `nodes`.
  - Cycle detection walks **every** node, not just those reachable from `root`, so an
    unreachable cycle is still an error.
  - `default_config_path()` is `Path(__file__).resolve().parents[2] / "config" / "tree.json"`.
    If the package is ever moved, that index changes — it's the one path assumption here.
  - `Tree.branch(node_id)` is the typed accessor for branch nodes; US-004/US-005 should use it
    instead of `isinstance` checks scattered around.
  - The sample tree has 8 nodes (3 branch, 5 leaf) — useful for US-003's `node_count` assertion.

- **Learnings for future iterations:**
  - **`generate()` returns `[]` as a normal result** (no tool applied, or unparseable
    output). US-005's `empty_response` termination reason is exactly this case.
  - **The declared `enum` does NOT constrain decoding.** `grammar.tool_call_grammar` builds
    the grammar from parameter *names* only, with `{}` as each value schema. So the model can
    return an argument value outside the configured `enum`. US-005 must validate enum
    membership itself after `generate()` returns — treating an out-of-enum value as a
    `none_of_these`-style non-answer rather than trusting it blindly.
  - Tool shape is `{"name", "description", "parameters"}` with `parameters` as JSON Schema.
    US-004 should emit exactly that; `none_of_these` gets
    `{"type": "object", "properties": {}, "required": []}`.
  - `NeuDecide.generate()` is **not** concurrency-safe (lazy `self._ll_tokenizer`), hence the
    lock in `InferenceEngine`. US-007 still needs a thread executor to keep the event loop
    free; the lock just serializes the CPU work behind it.
  - Audio input: a NumPy `(samples,)` float32 array in `[-1, 1]` at 16 kHz is the shape
    US-006 should decode to. `model.sample_rate` is the authoritative rate.
  - `TestClient` must be used as a **context manager** for lifespan to run at all; a bare
    `TestClient(app).get(...)` silently skips startup and `app.state` is never populated.
  - A `pydantic.BaseModel` return annotation on a route is how field names/types get pinned
    for the PRD's exact payload shapes — useful for US-007's event schemas too.
