## Codebase Patterns
- Quality checks run from `backend/`: `../.venv/bin/ruff check . && ../.venv/bin/mypy callcompass && ../.venv/bin/pytest`, plus `node --check frontend/*.js`. The venv is at the REPO ROOT but the configs are in `backend/pyproject.toml`, hence the `../`.
- mypy is strict: every test needs `-> None`.
- The ONLY frontend test runner is pytest driving `node` via `backend/tests/*_fixture.mjs`. Those tests SKIP silently when `node` is absent, so confirm pytest reports 0 skipped before believing the frontend is covered.
- All config models in `tree.py` are `extra="forbid"` (`_Strict`). Removing a schema field therefore gives stale-config rejection for free - never hand-write a "this field is no longer allowed" validator.
- Pydantic field names in `traversal.py` ARE the SSE wire format. Changing one changes the frontend contract; check the PRD and the `*_fixture.mjs` readers in the same commit.
- Editing `config/tree.json` by regex beats round-tripping it through `json.dump` - a reformat churns the whole file and buries the real change in the diff. Validate with `json.loads` after the regex, before writing.
- Removing a field from `LeafNode` is inherently atomic: schema + `config/tree.json` + `Completed` + tests all break together and must move in one commit.

## 2026-10-11 - US-002 - Design tokens and visual foundation
- Converted `frontend/styles.css` in place to a token-driven stylesheet: added a `:root` block with a 7-step type scale (`--text-2xs` .. `--text-xl`, plus two SVG-specific sizes `--text-tree-label`/`--text-detail` since those render at a fixed physical size), a 10-step spacing scale (`--space-0` .. `--space-9`, with `--gap` aliased to `--space-7`), a radius scale (`--radius-sm/md/lg/full`, `--radius` aliased to `--radius-md`), and a 3-step elevation scale (`--elevation-1/2/3`, applied to `.column`/`.result` for a subtle lift).
- Added the required semantic colour tokens (`--bg`, `--surface`, `--surface-raised`, `--border`, `--text`, `--text-dim`, `--accent`, `--accent-dim`, `--warning`, `--live`) plus extras the existing design actually needed: `--success` (the green used for leaves/completed), `--error` (aliased to `--live`), and a `-fill`/`-surface`/`-surface-raised`/`-border` tint family per semantic colour (`--success-fill`, `--warning-surface`, `--error-border`, etc.) so every one of the dozen near-duplicate hex shades in the original file got a name instead of being collapsed into one token that would have changed the look.
- Dark theme keeps every original hex value (just moved into tokens) so the already-shipped, presumably-tuned contrast didn't change. Light theme is new, under `@media (prefers-color-scheme: light)`, built from GitHub Primer's documented AA-safe light-mode fg/subtle-bg pairs (`#1f2328`/`#59636e` text on `#ffffff`/`#f6f8fa`, `#0969da` accent, `#9a6700` warning, `#cf222e` live/error, `#1a7f37` success) rather than invented colours, specifically so the contrast requirement didn't depend on guesswork.
- The `pulse` keyframes' two `rgb(248 81 73 / x%)` literals became `color-mix(in srgb, var(--live) x%, transparent)` so the recording-halo animation is also token-derived in both themes rather than hardcoding red.
- `frontend/waveform.js`: replaced the two hardcoded hex constants with `readColorToken(name, fallback)`, which calls `getComputedStyle(document.documentElement)` and falls back to the original hex when `getComputedStyle`/`document` don't exist (the node test harness). Colours are read once in the constructor (`this.idleColor`/`this.liveColor`) rather than per frame.
- No markup changed (index.html is untouched - that's US-003's job) and no selector was dropped; it was a straight token conversion of the existing 618-line file.
- Files changed: frontend/styles.css, frontend/waveform.js
- Checks: ruff/mypy/pytest clean (180 passed), `node --check frontend/*.js` clean.
- Browser verification: started uvicorn on :8123, loaded the page in chrome-devtools MCP, screenshotted default (light - the automation profile's OS preference) and emulated dark via `emulate(colorScheme)`. Both render identically in layout, only the palette differs; no console errors besides a pre-existing unrelated `favicon.ico` 404. No visual regression.
- **Learnings for future iterations:**
  - The chrome-devtools MCP server can get stuck with "The browser is already running for .../chrome-profile" if a prior Chrome process bound to that dedicated automation profile is still alive (e.g. from an earlier/crashed session). Fix: `ps aux | grep "chrome-devtools-mcp/chrome-profile"` and kill those pids (safe - it's a dedicated automation profile, not the user's real browser), then retry `list_pages`.
  - `node --check frontend/*.js` must be run from the repo root, not from `backend/` - the glob won't match if your cwd is wrong and zsh will error with "no matches found" rather than silently passing.
  - Chrome's automation profile apparently defaults to light `prefers-color-scheme`; don't assume a fresh screenshot is the dark theme without checking or emulating explicitly.
  - Pattern for future CSS/token work: when a file has many near-duplicate but not-quite-identical hex values for conceptually the same role (e.g. several dark-green card backgrounds), give each its own named token rather than forcing them into one - consolidating too aggressively is itself a visual change, which a pure "tokenize in place" story should avoid.
